# PR #134: Let the model refine a search before it answers: a capped search_site tool (#110)

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/pull/134
- Branch `task/WCP-0072-search-site-tool` into `main`, +9901 −43 in 56 files

One `answer_question` call did everything, so a vague or two-part question could not be refined. This adds a `search_site` tool, with every limit decided by code.

**What changes**
- `search_site(query, section?, page_type?)` returns up to 4 cited passages with titles, each cut to 400 characters (the text the model sees stays under 2,600 characters whatever the site size).
- Code caps it: 3 searches and 3 trips back to the model per turn; a filter that finds nothing is dropped once; `answer_question` takes the section and page type a search showed and does the same; at most 3 lookups of any kind per turn.
- Quote-only is unchanged: the spoken answer is still a quote from a cited passage, or the same "I don't know". Passage text reaches the model fenced as data.
- Stacked on #109 and #108. Not wired into the live site (that waits for per-business config, #103).

**How to verify**
`npm run check` (15 new tests, including a model that never stops searching and a poisoned passage).

**Before and after**

| | Before | After |
|---|---|---|
| Refine a vague question | one `answer_question` call | `search_site`, then `answer_question` with a section |
| Tool calls per turn | uncapped | 3 searches, 3 lookups |
| Search result size | n/a | 4 x 400 characters, fixed |
| Answer shape | quote with citation or "I don't know" | the same |

**Unchanged**: quote-only answers, the "I don't know" path, the form tools.
