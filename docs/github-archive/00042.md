# Issue #42: Make the repo public so main can require CI before auto-merge

- State: closed (2026-11-01)
- Opened by Pukujan on 2026-11-01

- Labels: account:agent-or-unmapped, needs-filer-stamp, needs-impact-evidence, needs-record-context, needs-release-relevance, observational-issue, ontology:oio-1.1.0, ontology:project-1.0.0, proposal, relation:related, status:open, priority:1, type:operational

### Summary

Auto-merge in this repository merges pull requests at once, without waiting for CI. The repository is private and its owner, the `Pukujan-lab` organization, is on GitHub's Free plan, so branch protection and rulesets are refused. On 2026-11-01 the owner chose to make the repository public, which makes protection free, and then require the `gates` check on `main`.

### Identity and Lineage

Leaf: this issue. Parent: none. Depends on: none. Related: #29 (CI on the VPS runners), #38 and #40 (merged before their checks finished).

### Acceptance Criteria

- The repository is public.
- `main` requires the `gates` check to pass before a pull request merges.
- A pull request with auto-merge on waits for `gates` instead of merging at once.

### Boundaries and Next Action

In scope: the repository's visibility and `main`'s protection. Out of scope: the org's plan, and other repositories. Next action: change the visibility.

### Symptoms

1. **Auto-merge doesn't wait.** PR #40 merged at 02:12:14 UTC, seconds after its last push, while CI was still running.
2. **Protection is refused.** `GET /repos/Pukujan-lab/voice-agent-research/rulesets` returns 403: "Upgrade to GitHub Pro or make this repository public".

### Hypotheses (unverified)

None. The cause is the plan, as GitHub's 403 response says.

### Counter-signal

CI did pass on the merged heads of #38 and #40, so nothing broken has merged so far.

### Honest Caveat

Making the repository public exposes its whole history. Before the change, a pattern scan of all 64 commits found no stored keys (3 matches, all code reading keys from the environment). The owner said the repository is safe to publish.

### Problems vs Gaps

Problem: checks don't gate merges. Gap: none.

### Proposal *(proposal)*

Make the repository public, then require `gates` on `main`. Neither exists yet.
