A live call left no record you could look up: the page traced a few backend calls with what the caller said masked, and the voice agent wrote its turn timings to a local `speech/turns.jsonl` that nothing read.

## What changes

Every call is now one Phoenix session in the `chatbots-factory` project, sent through Octo, with nothing masked. That follows the owner's direction on #17: each business decides what it keeps.

- **The page records the call** (`widget/calllog.ts`, new).
  - When the call ends, a `call` span records the business, pages visited, device and browser, voice stack, picked language, start and end times, and the outcome. The outcomes are finished, booked, abandoned, handed to a person, fell back to text, agent never answered, and error.
  - Each turn gets a `turn` span with:
    - what was heard and the reply
    - the decision and why
    - the desk's model and prompt version (`desk.prompt_version`, a hash of its prompt and tools)
    - the guide passages quoted
    - the time to decide, and the speech timings and confidence the agent sent
  - The turn's children hold:
    - each tool call (name, arguments, result)
    - each decision 0011 confirmation (risk score and band, the read-back, the caller's answer, whether it counted as yes)
    - each action the code lock blocked
    - each correction
  - A `failure.<kind>` span is sent as soon as something goes wrong. This covers a failed backend or RPC call, voice falling back to text, the 20-second no-agent cutoff, and an error in a turn.
- **The voice agent records its side** (`speech/telemetry.py`, new; it replaces `turns.jsonl`).
  - A `voice.turn` span for each turn holds the end-of-turn wait, speech-to-text time, deciding time, time to first audio, barge-ins and the speech model's confidence. The confidence comes from Parakeet's token log-probs, added to `/stt` in `speech/server.py`.
  - A `voice.failure` span records errors and failed RPC calls.
  - A `voice.call` span is sent when the room closes. These spans carry the page's call id, so they land in the same session.
- **Evals can score a call** (decision 0005). They `POST /api/score {call, turn?, name, score, label, explanation}`, and the score becomes a Phoenix span annotation on that turn's span or the call's span. A span this server didn't write gets an evaluator span in the session instead.
- **`/api/trace` takes the widget's spans** and checks their size and shape. `widget/mask.ts` is gone. The server now flushes its batched spans before it stops; before that, a call span sent at hang-up could be lost.

## Before and after

| | Before | After |
|---|---|---|
| Where a call lives | Loose traces, no session | One Phoenix session per call id |
| What the caller said | Masked | Recorded in full |
| Agent timings | `speech/turns.jsonl` on the machine | `voice.turn` spans in the same session |
| Outcome, device, stack | Not recorded | On the `call` span |
| Confirmations and code-lock blocks | One `confirm` span per fill | Children of the turn, with risk, band, answer and yes |
| Eval scores | Nowhere to put them | `POST /api/score`, which writes a Phoenix span annotation |
