# PR #135: Read records through business-declared, read-only lookups (#111)

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/pull/135
- Branch `task/WCP-0073-declared-lookups` into `main`, +10517 −43 in 60 files

Nothing could read an order, an appointment or a price from a table. This lets a business declare read-only lookups, and code runs exactly those.

**What changes**
- `copilot-engine/src/lookups.ts`: a business declares lookups (typed parameters, readable fields, a risk score). The model only names one and supplies values; code checks each value, binds it as a `$n` parameter of a statement built from the declaration, returns only the declared fields, adds the business's scope, and for anything about a person returns only the verified caller's own rows. The spoken line is composed by code.
- Risk (decision 0011): under 56 runs; 56 to 90 waits for a recorded yes (the yes runs it without asking the model); 91 and up goes to a person. Anything about a person needs a verified caller first, and never scores below 45.
- `Desk` takes `lookups` and `caller`; docs in `docs/lookups.md`.
- Stacked on #110, #109 and #108.

**How to verify**
`npm run check` (17 new tests): 17 hostile values (quotes, `OR 1=1`, `DROP TABLE`, `UNION SELECT`, null byte, `$1`) change and leak nothing and the statement text never varies; objects, arrays and 5,000-character strings never reach SQL; the same order number at two businesses stays separate; a business or client id from the model is ignored; an unverified caller runs no SQL.

**Before and after**

| | Before | After |
|---|---|---|
| Look up an order, appointment or price | not possible | declared lookups |
| SQL written by the model | n/a | never |
| Fields that can be read out | n/a | only the declared ones |
| Caller not verified, lookup about a person | n/a | refused, no SQL run |

**Unchanged**: caller verification itself (`/api/verify`), the form tools.
