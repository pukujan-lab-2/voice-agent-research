# PR #58: The live site's pages talk through the v2 desk, with LFM3 writing the replies

On 2026-10-31 the Brindlewick tax site answered "can I ask you about taxes?" with unrelated IRS passages, because every page still ran the old rules engine. The v2 desk (merged in #37) can tell a question about itself from a tax question, but it was never wired into the site.

## What changes

- **Form pages** (clinic, appliance, pricing, IT desk, pension, `/tax/book`) run on the v2 desk. LFM3 writes the replies and picks actions through tools. Code still does every read-back, refuses to type a value in without a clear yes, and never presses submit. Spoken calls reach the same desk, because LiveKit transcripts go through the widget's `send()` like typed text.
- **The `/tax` question page** runs a question-only desk. A question about the assistant gets a short answer from LFM3, with no guide search. A factual question is looked up and quoted with its source opened in the site's viewer. LFM3 is never allowed to state a fact itself: if its reply contains an amount, a deadline or a rule, the desk looks the question up instead, and says it doesn't know if nothing answers.
- **New endpoint `POST /api/desk`** lends the browser one LFM3 turn. It takes only the desk's six tools and limits message size and count. It returns 503 when no model is set, and the desk then runs that call on its rules.
- **The desk learned what the site's forms need:** codes read back letter by letter ("C, P, 2, 0, 0, 0"), dates and digit fields, optional fields that "none" leaves blank, first-name and last-name fields that take one word, and the keyboard offer after a second miss on a serial, phone or email (as v1 did). It also reads back an answer itself when LFM3 ignores it, which it did twice in the live runs.
- **`memory.ts` loads in the browser** (no top-level `node:` imports).
- **Scene tests** check v2's behaviour instead of v1's exact sentences. Every value must be read back while the field is still empty and typed in only after the yes; nothing is sent; the person presses the button.

## What stays unchanged

The rules engine stays for caller verification (`verify.ts`) and for any turn the model can't serve. Drafts still carry a half-filled form across page changes. Returning-customer memory and call resume stay off on the site, because they need a server-side store (#57). Per-field risk scores from decision 0011 are #56: this PR reads back every field, which is 0011's 31–55 band, and code still locks every fill behind a yes.

Known failures that also happen on `main` and are not touched here: the stubbed voice scene and the voice-layout checks hit a blocked microphone since the LiveKit switch (#38); the scenes time out after pressing the page's own submit button on `/tax/book`; and the no-model keyword search answers two manual questions with the wrong page. The real-audio test (`tests/voice-call.ts`) was not run, because the speech stack on this machine is serving the owner's live test.
