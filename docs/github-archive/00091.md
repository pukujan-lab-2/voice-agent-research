### Summary

CI never runs an answer, so a change can bring back a bad answer unseen. This runs the replay cases on every pull request without keys, and the full live set nightly and on every `production` move.

### Identity and Lineage

Leaf: this issue. Parent: #88. Depends on: #90. Related: #17, #12, #13, #15.

### Acceptance Criteria

- On every pull request a CI job replays the cases against the shipped answer path with recorded search results and an offline model, needs no keys, and fails the PR on a regression.
- Nightly and on every `production` move, the full live set runs; the result is posted on a standing issue.
- When a rule's failure count rises, an issue opens by itself.
