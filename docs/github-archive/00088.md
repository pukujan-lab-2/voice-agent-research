# Issue #88: Make real calls improve the copilot: flag, replay, gate, re-check, propose

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/88

### Summary

The owner asked whether the copilot has a pipeline that makes it better from real calls. It doesn't. The eval harness (`eval/`) runs by hand on made-up questions, CI checks only lint, types and the offline engine scenarios, and a bad real turn is found only when the owner complains. On 2026-11-01 a real call shows what that costs: the copilot said "I don't know" to "Can I file it from here?" although a passage in the search results says yes, and nothing flagged it.

This parent tracks one closed loop in five small pieces: a real turn gets flagged by plain code, becomes a replay case, a pull request cannot make it fail again, a deploy re-checks it live, and a routine files an issue for each failure pattern.

### Acceptance Criteria

- The loop runs end to end once: a flagged real turn becomes a replay case that fails, a fix makes it pass, CI blocks a revert, and the replay after the next deploy shows it live.
- No human spot check and no model comparison anywhere in the loop (decisions 0005 and 0001's "no bake-offs"); the flags and the case checks are plain code.
- Everything the loop stores lives in Octo (decision 0004); nothing edits or deploys production code on its own.

### Boundaries and Next Action

In scope: `eval/` scripts, one CI workflow, one scheduled workflow, one deploy-time workflow. Out of scope: fixing the flagged answers themselves (those are #12, #13, #15 and follow-up issues), the staff insights page (#17), the nyc-map-agent workspace (another app). Next action: build the first child (mine).

### Symptoms

1. **No loop.** Real bad turns reach the owner as complaints, not as failing tests.
2. **Gate misses answers.** CI never runs an answer; the engine scenarios use a rule model.

### Hypotheses (unverified)

- **H1. A handful of plain rules over spans finds the turns the owner would complain about.** Status: unverified. Would confirm: the rules flag the four bad turns from the 2026-11-01 17:10 call. Would refute: they miss one. Experiment: run the mining script on that call.

### Counter-signal

Rules over a few hundred spans will miss bad turns whose symptoms are not in the spans (a wrong but cited answer). Those stay with #15's held-out set.
