- Branch `feat/124-auto-promote` into `main`, +160 −4 in 7 files

Merged work sat on `main` until someone pushed `production` by hand, so fixes didn't reach the live site on their own.

## What changes

- `.github/workflows/promote.yml` (new): when CI passes on a push to `main`, it moves `production` to that commit by fast-forward, and Komodo deploys it within about 5 minutes. It never forces: if `production` has commits that aren't on `main`, it fails and leaves it alone. Pull requests and forks never promote.
- [Decision 0016](docs/decisions/0016-merges-go-live.md) records the rule and replaces 0015. A person can still move `production` by hand, for example to roll back one commit, and there is no automatic revert.
- `deploy/README.md`, PROJECT.md's status row and the decisions index say the same. Adds the task record `tasks/TASK-WCP-0050-auto-promote.md`.
