The offline scene suite died in its voice scene, so a full run printed no summary and never reached the phone layout checks — every demo change since #61 merged without an end-to-end run. This makes the run finish and say what it could not check.

## What changes

- **The voice scene says why it cannot run.** A call has run on LiveKit since #61 and needs a microphone; headless Chromium refuses it, the widget falls back to typing, and the scene's fake speech services are never consulted. It now waits for either a spoken question or the typing fallback and, on the fallback, prints `SKIP  voice: this browser refuses the microphone…` instead of waiting 30 s for a question that cannot arrive.
- **Skips are counted, not passed.** The summary reads `live-site (offline): 172/178 (5 skipped)` and one `skipped …` line follows for each, so a scene that did not run is visible at a glance.
- **The layout scene's call checks say what they measure.** Its eight "voice" checks are now "call bar"; the three that need a spoken turn skip with the same microphone reason, and the five that only measure layout still pass.
- **Three more checks fail instead of killing the run.** The tax form's submit (#19), the tax-phone page load (it waited for the network to go quiet, which never happens offline) and the guide library (no document store offline) now record a failure or a skip rather than throwing.
- The layout scene's dead speech stub is gone: neither `SpeechRecognition` nor `speechSynthesis` is read by the widget any more.

## What stays unchanged

No product code: the widget, the engine, the speech stacks and every page are untouched. A browser with a microphone still gets a voice call; the skip only fires when the browser refuses one.

## What still fails, recorded rather than hidden

All six failures are older than this change: two offline guide lookups ("warranty page 8", "processing time page 4"), the tax form's submit (#19), the FAQ list reading an empty document store, and two timing checks that expect a wait line the offline model answers too fast to show. The suite still exits 1 until those are fixed — that is the honest result, not a regression.

The voice scene still cannot run headless at all. Giving it a real path needs Chromium's fake media device plus a local LiveKit server, which #69 keeps as the next step.
