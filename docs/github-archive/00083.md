Only two of the five voice stacks had real-audio or tool-calling tests, and nothing measured how well each one hears and speaks the languages it claims. That leaves businesses picking stacks nobody has measured, which breaks the lab's rule that every version gets tested.

## What changes

- New `demo/live-site/tests/voice-matrix.ts` (`npm run test:voice-matrix`). It runs every stack in `speech/stacks.json` one at a time, so the speech server swaps models instead of loading them all. For each stack and each language it claims, it measures:
  - **Hearing:** word errors (character errors for Chinese) on recordings of people reading aloud, against transcripts written by people. The sources are Google FLEURS for en, fr, pt, zh and hi, and Multilingual LibriSpeech for es and it, both CC-BY-4.0.
  - **Speaking:** the stack's voice saying the same sentences, heard back by Whisper on the `multilingual` stack, plus the time to its first sound.
  - **Tool calls:** `tests/voice-tools.ts` on the stack.
- Each case is a Phoenix trace through Octo, one session per run. The trace links the audio the stack heard and the audio it spoke, both stored in Octo files, so any failure can be played back. The report goes to Octo as well as the console.
- `--llama-host mac-pro|windows` reaches that machine's LFM3 over an SSH tunnel.
- `tests/voice-tools.ts` accepts any stack and picks the model from the stack's `thinks` setting.
- Task record `tasks/TASK-WCP-0019-voice-matrix.md`.
