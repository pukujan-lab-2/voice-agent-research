## What changes

- Pushing to `production` deploys the lab with no hand steps ([decision 0015](docs/decisions/0015-production-branch-deploys.md), which replaces 0007). The site goes to https://copilot.design-bakery.com.
- `deploy/` (new):
  - **VPS:** `web.Dockerfile` (the site and `/api`), `agent.Dockerfile` (the voice agent) and `docker-compose.vps.yml` (those two, LiveKit, and the bridges to the Pro's tunnels).
  - **Deploy script:** `vps/autodeploy.sh` builds both images tagged with the commit, swaps them in, waits for `/api/health` and rolls back if it fails. Komodo runs it when `production` moves, the same way nyc-map-agent deploys.
  - **Pro:** `pro/` holds the launchd jobs for the speech server (all five stacks, swapped per call) and its reverse SSH tunnel to the VPS, plus `update.sh`, which moves the Pro's checkout to `production` every 5 minutes.
  - **README:** says what runs where, which keys are needed and how to check each part.
- `server.ts`:
  - The page is told LiveKit's public address (`LIVEKIT_PUBLIC_URL`), and `/rtc` is passed through to LiveKit, so signalling uses the site's own hostname.
  - Behind the tunnel, the visitor's address comes from `CF-Connecting-IP` (`TRUST_PROXY=1`), so rate limits apply to each visitor.
- PROJECT.md's status table and the decisions index are updated, and the task record `tasks/TASK-WCP-0020-production-deploy.md` is added.
