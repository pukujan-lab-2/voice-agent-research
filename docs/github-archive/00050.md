# Issue #50: CI can't start since the repo went public: move to GitHub-hosted runners

- State: closed (2026-11-01)
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/50

### Summary

Since the repository went public (#42), no CI job starts. The workflows ask for the VPS runner pool (`self-hosted, org-pool`), and the `Pukujan-lab` organization's only runner group doesn't allow public repositories. Pull requests #46, #47 and #49 sit with `gates` queued and can't merge. On 2026-10-31 the owner chose GitHub-hosted runners, which are free for public repositories and keep outside code off the VPS.

### Identity and Lineage

Leaf: this issue. Parent: none. Depends on: #42 (repository made public). Related: #29 (moved CI to the VPS pool while private).

### Acceptance Criteria

- `gates` and the stack-train check run on `ubuntu-latest`.
- The `OIO_RUNS_ON` repository variable is removed, so the OIO issue workflows use their `ubuntu-latest` default.
- A new decision replaces 0008 with the runner change.
- Queued pull requests (#46, #47, #49) get a `gates` result.

### Boundaries and Next Action

In scope: `.github/workflows/ci.yml`, the `OIO_RUNS_ON` variable, the decision records. Out of scope: the org's runner group settings, which stay closed to public repositories. Next action: change `runs-on`.

### Symptoms

1. **CI never starts.** Runs for `fix/43-ringback`, `feat/44-tax-demo-link`, `fix/48-capability-questions` and `main` stayed queued for over 15 minutes with both VPS runners online and idle.
2. **Runner group closed to public repositories.** `GET /orgs/Pukujan-lab/actions/runner-groups` shows the Default group with `allows_public_repositories: false`.

### Hypotheses (unverified)

- **H1. The runner group refuses jobs from public repositories.** Status: confirmed by the runner group setting and idle runners with matching labels.
