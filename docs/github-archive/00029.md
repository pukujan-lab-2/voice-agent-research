# Issue #29: CI here runs on a broken MacBook Pro runner, because this private repository is outside the Pukujan-lab organization that owns the VPS runners

- State: open
- Opened by Pukujan on 2026-10-31
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/29

### Summary

This repository's CI runs on `macbook-pro-chatbots`, a self-hosted runner on the owner's MacBook Pro, because `ci.yml` asks for `[self-hosted, chatbots]` and the repository variable `OIO_RUNS_ON` names the same label. That runner can no longer set up Python (`actions/setup-python` fails with `mkdir: /Users/runner: Permission denied`), so on PR #28 the close check and the stack manifest check failed before running anything. Services and CI have moved to the VPS; its runner pool (`org-pool`) serves only private repositories in the `Pukujan-lab` organization, and this repository is private under the personal `Pukujan` account. The owner chose to move it into `Pukujan-lab` and run CI on `org-pool`.

### Symptoms

1. **Python setup fails on the Pro runner.** On PR #28, `actions/setup-python@v5` on `macbook-pro-chatbots` failed with `mkdir: /Users/runner: Permission denied`.
2. **Two checks failed without running.** `close / close` and `stack-train / Manifest agrees with the release train` failed at that step, and #28 merged anyway because they are not required.

### Hypotheses (unverified)

- **H1: the runner has no tool cache it may write.** Status: confirmed by the log: `setup-python` tries to create its default tool cache under `/Users/runner`, which this machine's runner user cannot create. Would refute: the same step passes on the runner after a rerun.
- **H2: this repository was never moved off the Pro.** Status: confirmed: `vps/PLAN.md` in `Pukujan-lab/server-management` moves CI to the `org-pool` runners for private `Pukujan-lab` repositories, and this one is outside that organization.

### Counter-signal

Earlier runs on `macbook-pro-chatbots` passed, so the runner worked until recently; the tool cache may have been cleared when other services left the Pro.

### Honest Caveat

The cause of the permission change on the Pro was not investigated; the fix moves CI off that runner instead of repairing it.

### Problems vs Gaps

- Problem: CI checks here fail before running (symptoms 1 and 2).
- Gap: this repository was missed when private repositories moved to the VPS runner pool.

### Proposal *(proposal)*

None of this exists yet. Transfer the repository into `Pukujan-lab`, switch its runner labels to `org-pool`, and update `adopters.json` in agent-stack-train to the new name.
