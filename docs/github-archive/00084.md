# Issue #84: Deploy the copilot lab from a production branch that deploys by itself

- State: closed (2026-11-01)
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/84
- Labels: status:resolved

### Summary

The copilot lab runs only on the owner's Mac at 127.0.0.1:8787, so nobody can try the demo sites or a voice call from a phone or another computer. The owner now wants everything deployed with a pipeline: a `production` branch that deploys by itself when it moves. This replaces decision 0007 ("not hosted yet").

### Identity and Lineage

Leaf: this issue. Parent: none. Depends on: none. Related: #82 (voice matrix), decision 0007 (replaced), decision 0002 (LiveKit), decision 0014 (models swapped per stack), Pukujan-lab/server-management `vps/PLAN.md`.

### Acceptance Criteria

- A `production` branch. When it moves, Komodo deploys it to the VPS within about 5 minutes: build the image tagged with the commit, swap the container, wait for its health check, and roll back if that fails. This copies nyc-map-agent's `deploy/vps/autodeploy.sh` pattern.
- The VPS runs the site and its API, the LiveKit server and the voice agent. Text chat uses LFM3 on the Pro through the existing `lfm3-bridge`.
- The speech models stay on the Pro, where they run on Apple's GPU and were tested. The Pro's speech server sits behind a reverse SSH tunnel to the VPS, like the LFM3 tunnel. When `production` moves, the Pro updates its own checkout and restarts its speech server.
- All five voice stacks work on the deployed site.
- The site is public at https://copilot.design-bakery.com through Cloudflare tunnel A. LiveKit's signalling goes through the same hostname, and call audio reaches the VPS directly on one TCP and one UDP port.
- Keys live in an env file on the VPS, copied without being printed, and never in git.
- Decision 0015 replaces 0007. Komodo's stack and action, and `vps/PLAN.md`, are updated in server-management.

### Boundaries and Next Action

In scope: the Dockerfile and compose file, the autodeploy script, the Pro's speech service and tunnel, the Komodo resources, the decision, the plan update and one route on tunnel A. Out of scope: phone calls (SIP), multiple businesses stored on the server, scaling past one VPS. Next action: build the deploy files.

### Symptoms

1. **Local only.** `server.ts` binds 127.0.0.1 and starts LiveKit in dev mode with its built-in key.
2. **The hostname is dead.** `copilot.design-bakery.com` resolves but returns Cloudflare error 530 (checked 2026-11-01): it still points at gravebuster's tunnel, which is offline.

### Hypotheses (unverified)

- **H1. WebRTC media reaches the VPS's public address on one UDP port.** Status: unverified. Would confirm: a call from outside the tailnet connects. Would refute: the connection times out (a provider firewall). Experiment: the deployed voice test.

### Counter-signal

The Pro is a cold, on-demand AI host under `vps/PLAN.md`. If it is asleep, voice calls fail until it wakes, but text chat keeps working.

### Honest Caveat

Voice depends on two machines (the VPS and the Pro) and the tunnel between them.
