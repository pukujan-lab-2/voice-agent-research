# Issue #57: Resume dropped calls and remember returning customers on the live site

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/57

### Summary

A caller whose call drops on the live site starts the form over by voice, and a returning customer is asked for their details again. The v2 desk can resume a dropped call and remember a customer who opts in, but only with a store that keeps state between visits. The live site has no such store, so the #16 wiring leaves both off.

### Identity and Lineage

Leaf: this issue. Parent: none. Depends on: #16. Related: none.

### Acceptance Criteria

- The site's backend keeps resume state and opt-in customer memory, with salted keys as `copilot-engine/src/memory.ts` uses now.
- The widget passes a session id the desk can resume from.
- A scene test drops a call and resumes it, and a second visit finds an opted-in customer.

### Boundaries and Next Action

In scope: `demo/live-site/api.ts` and `widget/sdk.ts`, plus a store the VPS can host. Out of scope: the page's own browser draft, which already carries answers between pages within one visit. Next action: pick the store (Octo, per the single-store rule) and its retention.

### Symptoms

1. **A dropped call starts over.** The desk's resume line never runs on the site.
2. **Returning customers repeat themselves.** The desk's memory is never offered on the site.

### Hypotheses (unverified)

- **H1. Octo can hold the desk's memory records with an expiry.** Status: unverified. Would confirm: a write and read through the Octo API with a time-to-live. Would refute: no expiry or no per-key delete. Experiment: one round trip against the chatbots workspace.

### Counter-signal

Nothing personal is stored today, which is the safest place for a demo to be.

### Honest Caveat

Keeping customer details needs a retention rule and a way to delete them. The desk already handles "forget me", but the site has no privacy note for it.

### Problems vs Gaps

Gap: no server store for the desk's state.

### Proposal *(proposal)*

Back `memory.ts`'s store interface with Octo through the site's API. None of this exists yet.
