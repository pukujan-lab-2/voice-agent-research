A new business has no way to put its own site into Octo: the IRS library was loaded by one-off scripts. This adds one pipeline for any business.

**What changes**
- New `ingest/` package: a sitemap or start URL plus HTML, PDF and Markdown in; clean passages with url, title, section, page type, language and last-modified out, into `<business>/<language>/<page type>/…` documents in Octo plus two tables (`site_pages`, `site_passages`).
- Re-crawl asks the site first (ETag, Last-Modified), rewrites only changed passages, removes deleted pages, indexes duplicates once, and refuses a mass delete (a broken sitemap) unless told.
- OSS picked: trafilatura (HTML to clean Markdown and metadata), Docling (PDF, already used here), httpx (conditional GETs). Crawl4AI is not included; nothing needs JavaScript rendering yet. Details in `docs/ingest.md`.
- `irs_store.py` and `irs_ingest.py` (and `lib_ingest.py` through them) now use the shared Octo client instead of their own copies.
- CI and `npm run check` run the new Python tests.

**How to verify**
`npm run check` (31 new Python tests over a real local HTTP site). Live: loaded, re-ran (0 writes), deleted a page and searched with a title prefix on the real Octo, then cleaned up. IRS scripts read the live workspace (145,519 passages) through the shared client.

**Before and after**

| | Before | After |
|---|---|---|
| Putting a new business's site into Octo | not possible; the IRS scripts were one-off | `uv run site-ingest --business acme --sitemap URL --docs DIR` |
| Re-run with nothing changed | n/a | 0 writes (the site answers 304; hashes match) |
| One page edited | n/a | only the changed passages are replaced |
| Octo client code | copied in three IRS scripts | one module, `ingest/src/site_ingest/octo.py` |

**Unchanged**: IRS fetchers' parsing, the library data, the engine.
