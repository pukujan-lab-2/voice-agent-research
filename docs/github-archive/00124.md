# Issue #124: Merges to main should go live by themselves when CI passes

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/124

### Summary

A merge to `main` doesn't go live by itself. Someone has to run `git push origin main:production` (decision 0015), so merged fixes sit unseen on the live site until a person remembers. The owner asked for merges to deploy without that step.

### Identity and Lineage

Leaf: this issue. Parent: none. Depends on: none. Related: #84 (the deploy pipeline, closed), decision 0015, the live-traces loop #88 (its post-deploy replay and warnings read `production`).

### Acceptance Criteria

- When CI passes on a push to `main`, a workflow moves `production` to that commit by fast-forward, and Komodo deploys it within about 5 minutes, as before.
- It never forces. If `production` has commits that are not in `main`, it stops and says so in the run summary.
- Only a push to `main` that passed CI promotes; pull requests and forks never do.
- Decision 0016 records the rule and replaces 0015's "push by hand" consequence; `deploy/README.md` says the same.

### Boundaries and Next Action

In scope: `.github/workflows/promote.yml`, decision 0016, the deploy README, a task record. Out of scope: reverting a bad deploy automatically (the loop's #123 is warn-only), changes in server-management. Next action: add the workflow; it can't be tested end to end until GitHub Actions starts runs again.

### Symptoms

1. **Merged work waits for a hand push.** `production` was created by hand on 2026-11-01 and moves only when someone pushes it.

### Hypotheses (unverified)

- **H1. The `GITHUB_TOKEN` of a `workflow_run` job may push `production`.** Status: unverified. Would confirm: the first promotion after Actions resumes. Would refute: a permission error in the run; then a fine-grained token in a repository secret is needed, and the owner adds it.

### Counter-signal

Every merge going live removes the human gate. Quality gates (CI today, the loop's replay checks later) are the only thing between a merge and the live site.

### Honest Caveat

GitHub Actions has not started a run since about 17:40 UTC on 2026-11-01, org-wide, so this cannot run until that clears.

### Problems vs Gaps

Gap: no automatic path from a passing merge to the live site.
