# Issue #106: Answer from the top search hit when the judge returns nothing but the hit says the question's own words

- State: closed (2026-11-01)
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/106

### Summary

On 2026-11-01 a caller asked "Can I file it from here?" and the copilot answered "I don't know", although the first search result began "Yes, you can file an original Form 1040 series tax return electronically". The judge model returned no passage, and the Guide takes that as "nothing answers". This is the first bad turn the mining and replay loop (#88) found; fixing it is what proves the loop works end to end.

### Identity and Lineage

Leaf: this issue. Parent: #88. Depends on: #90 (the replay case, merged) and #91 (the gate). Related: #15 (held-out accuracy). Replay case: judge-dropped-answer, session 7d689fcd-fe99-439c-8350-6305244e2875, turn 6.

### Acceptance Criteria

- When the judge names no passage and the top search hit says nearly all of the question's own content words (at least three, at least three quarters of them), the Guide answers from that hit.
- The dropped-answer replay case passes on its recorded results, becomes `guarded`, and the snapshot is exported in the same pull request.
- A question the library can't answer (for example one sharing only two words with the top hit) still gets "I don't know".
- Reverting the change fails `gates`.

### Boundaries and Next Action

In scope: `copilot-engine/src/guide.ts`, its test, the snapshot. Out of scope: the other six open cases (clarifying questions are #12, repeated quotes and invented offers are follow-ups). Next action: write the rule and its tests.

### Symptoms

1. **"I don't know" with the answer in the results.** The judge returned `{"id":""}` for "Can I file my tax return from here?" and again for "Can I file it from here?".

### Hypotheses (unverified)

- **H1. The judge model sometimes returns nothing for a yes/no question whose passage opens with "Yes".** Status: unverified. Would confirm: the same question gets an id on some runs and none on others. Would refute: it never returns an id. Experiment: replay against the live site; the first run on 2026-11-01 afternoon passed (an id came back), so the judge is not consistent.

### Counter-signal

The live site answered the same question correctly in one replay, so the judge's behaviour is not fixed. A word-overlap rescue is a floor under it, not a replacement.

### Honest Caveat

The rule is judged on one real case. It trades a missed answer for the chance of quoting a loosely related passage; the thresholds are chosen to keep that chance low and are covered by a test, not measured on the held-out set (#15).

### Problems vs Gaps

Problem: a wrong "I don't know". Gap: no measure of how often the judge drops an answer.
