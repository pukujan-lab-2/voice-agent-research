# Issue #73: Swappable multimodal models per task: LFM3-Omni and VL (later)

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/73

### Summary

The owner wants agents that can look at video, audio and images and help users in more ways, using LFM3-Omni, a vision-language (VL) model, or both. Like the voice stacks in decision 0012, these should be options picked per task by the owner, a business or a visitor, not one fixed model. This repo is the main lab and builder that many other apps, websites and customers adopt, so the choice has to be swappable and per business. This issue is for later; nothing is built yet.

### Identity and Lineage

Leaf: this issue. Parent: none. Depends on: #71 (lfm3-audio stack and tool-calling test, whose adapter and test this work would reuse). Related: decision 0012 (swappable voice stacks), decision 0009 (LFM3 writes replies), decision 0011 (risk sets confirmation).

### Acceptance Criteria

- A registry of model options per task (for example: reply, see image, watch video, hear audio), with a business-allowed list and a default, picked the same way as voice stacks (owner, then visitor from the allowed list, then business default).
- LFM3-Omni and a VL model each available as an option, once the owner approves their downloads.
- A visitor can share an image, a video clip or audio in a chat or call, and an agent using one of these options answers about it.
- The tool-calling test from #71 runs on each new option, with pass counts recorded.
- A decision record covers the registry.

### Boundaries and Next Action

In scope: the model-option registry, Omni and VL adapters, image/video/audio input in the chat and call, the tool-calling test on each option. Out of scope: #71's lfm3-audio stack, the staff insights page (#17). Next action (later, when the owner starts it): read the LFM3-Omni and Liquid VL model cards for sizes, inputs, languages and how to run them (llama.cpp/GGUF or Transformers), and post them here for the owner's approval before any download.

### Symptoms

1. **No vision or video input.** Agents take text and speech only.
2. **Model choice is per stack for voice only.** Decision 0012 covers how a call hears and speaks; there is no matching choice for what the agent can understand.

### Hypotheses (unverified)

- **H1. One llama.cpp adapter can serve LFM3-Audio, LFM3-Omni and a VL model.** Status: unverified. Would confirm: #71's adapter loads Omni and a VL model with only config changes. Would refute: either model needs a different runtime.

### Counter-signal

This Mac has 8 GB of memory; a multimodal model beside the speech models may not fit, so some options may need the Pro or another host.

### Honest Caveat

Facts about Omni in `docs/03-lfm3-omni-voice.md` come from earlier notes and have not been checked against the current model card.

### Problems vs Gaps

Gap: agents cannot see images or video, and there is no per-task model choice beyond voice.
