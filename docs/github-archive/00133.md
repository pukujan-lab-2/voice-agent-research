# PR #133: Search a site by section, page type and language, and measure it at 200,000 passages (#109)

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/pull/133
- Branch `task/WCP-0071-retrieval-at-size` into `main`, +9528 −31 in 53 files

Search could not be narrowed to part of a site, and nobody had measured it past 133,000 passages. A business with a huge site needs both.

**What changes**
- `SiteRetriever` (`copilot-engine/src/site-search.ts`): narrows by language and page type through Octo's title prefix, by section through the ids under that heading, and always to the business's own prefix; it drops any result outside the prefix even if Octo returns it. Octo has no metadata filter yet, so this is the stand-in (filed as octo-database#459).
- `eval/size/`: a synthetic site of any size loaded into a scratch Octo schema, timing Octo's own `match_chunks_hybrid`, scored with ranx through `eval/retrieval.py`; `eval/size/irs-live.ts` does the same for the live IRS library.
- What is slow is filed upstream with numbers: octo-database#391 (comment) and #459. No local copy of any data.
- Stacked on #132 (ingestion), whose title scheme it searches.

**How to verify**
`npm run check` (10 new tests). The figures are in `eval/out/synthetic-*` and `eval/out/irs-live`; the write-up is in `docs/retrieval-limits.md` (in the last PR of the stack).

**Before and after**

| | Before | After |
|---|---|---|
| Narrow a search by section, page type or language | not possible | all three; a filter never returns a passage outside it (tested) |
| Measured size | 133,000 passages (IRS), no recall figure by size | 10,000 / 50,000 / 200,000 synthetic plus 145,519 IRS |
| recall@10 on the synthetic site | n/a | 1.0 / 1.0 / 0.997 |
| 200,000 passages, one business's whole site | n/a | 2.1 s (0.24 s unfiltered; 0.27 s by section) |
| IRS library search, p50 | 8.8 s (2026-10-31 eval) | 1.5 s (live Octo, reranker on) |

**Unchanged**: how answers are chosen and quoted.
