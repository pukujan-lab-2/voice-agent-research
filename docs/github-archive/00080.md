# PR #80: Swap voice models in and out so only the stack in use is loaded

- State: merged (2026-11-01)

- Branch `task/WCP-0016-swap-models` into `main`, +276 −86 in 9 files, merge commit 64b800bc94dbcb3977db71c949e7821e2d8d99b2

The owner asked that voice models not run all at once, but the speech server kept every model it had loaded, and on this 8 GB Mac that pushed swap to 7.2 of 8.2 GB during one call. This makes the server keep only the models of the stack in use and swap the rest in and out.

## What changes

- `speech/server.py`: `Stacks` loads and unloads models by stack. A request that names another stack unloads what that stack does not use (Parakeet, Pocket TTS, Whisper with its graphics memory, Kokoro, and the llama.cpp server behind LFM3-Audio) and loads its own, after any request still running on the old models has finished. Models two stacks share stay. The default stack loads at start so its first call is fast (`--stack` or `SPEECH_PRELOAD`, where `none` loads nothing). A new `POST /load?stack=` does the swap ahead of the first request, and `GET /health` shows what is resident.
- `speech/agent.py`: every call asks for its stack to be loaded before it greets, so a swap never lands in the middle of a greeting.
- Decision 0014 records the rule and its numbers; decisions 0012 and 0013 and `docs/03` point to it.

## Before and after

| | Before | After |
|---|---|---|
| Models in memory | Parakeet and Pocket from start, plus every stack's models once used | one stack's models |
| Speech server footprint on `lfm3-audio` | 1.78 GB with `english-fast` still loaded | 0.31 GB, plus 0.60 GB in the llama.cpp server |
| After a Whisper stack was used | its 1,546 MB of graphics memory stayed | 3 MB (it is cleared on unload) |
| Swap-in time | n/a | 3.2 to 3.8 s for `lfm3-audio`, 6.8 s for `english-fast`, 4.7 s for `multilingual` |
| A swap asked during a reply | n/a | waits for the reply, which arrives complete |

## How to verify

`npm run check` passes (50 engine tests, 8 of 8 scenarios, ruff, tsc). The swap test was run on this Mac: the speech server, `POST /load` through five stacks in turn with the resident set and footprint read after each, then a swap asked while an 18 s reply streamed. A real LiveKit call that started with `english-fast` resident swapped to `lfm3-audio` in 3.3 s before its greeting, heard two lines and replied. The numbers are in decision 0014 and on [#71](https://github.com/Pukujan-lab/voice-agent-research/issues/71).

## What stays unchanged

The stacks, their languages, the code lock and the tests. The LFM3 text model that `english-fast` uses is on another machine and is not swapped.

## Limits

One pass of the swap test, one caller at a time, and macOS footprint as the memory measure (RSS undercounts on a swapping Mac). After the Whisper stack was swapped out, about 0.8 GB stayed with the process until the next swap-in.
