# Issue #101: Keep the model's prompt a fixed size however many fields the form has

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/101

### Summary

A form with 300 fields puts about 300 field lines in the system prompt and 300 more in the note added to every message, and the tool schema repeats every field name. A small model with a short context would fail, and the only guard today is dropping history after a context error. The model needs the current field, the next few and a one-line count of the rest. Code keeps every value.

### Identity and Lineage

Leaf: this issue. Parent: #100. Depends on: none. Related: #57.

### Acceptance Criteria

- Forms of up to 24 fields produce exactly today's prompt; the existing tests pass unchanged.
- Larger forms show the model the open field, the next few, a read-back that is waiting, the field to return to, the last few filled values, any field the visitor just named, and a one-line count of the rest. The tool schema stops listing every field name.
- Call history kept in memory is capped, so a 100-turn call holds no more than a fixed number of messages.
- Tests: a 300-field form and a 100-turn call keep every prompt under a fixed size (characters), every collected value is intact at the end, and none lands in the wrong field.

### Boundaries and Next Action

In scope: `copilot-engine/src/desk.ts` and a new test file. Out of scope: server state, config storage, model choice. Next action: write the window and the two tests.

### Symptoms

1. **Prompt grows with fields.** `systemPrompt()` and `stateNote()` both map over every field.
2. **Memory grows with turns.** `log`, `hist`, `turns` and `events` on the desk are never trimmed.
