# Issue #111: Read records through business-declared, read-only lookups with risk scores

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/voice-agent-research/issues/111

### Summary

Nothing reads an order, appointment or price from a table. A business declares read-only lookups in its config (typed parameters, which fields may be read out); code runs them as parameterized SQL on that business's own Octo tables and returns only the declared fields. The model never writes SQL. Each lookup has a decision-0011 risk score, and anything about a person needs caller verification first.

### Identity and Lineage

Leaf: this issue. Parent: #107. Depends on: none. Related: decision 0004 (Octo is the one store).

### Acceptance Criteria

- A lookup declared in config becomes a tool; the model supplies only typed parameter values.
- Only declared fields are returned; an undeclared field never appears (tests).
- SQL injection attempts in any parameter change nothing and leak nothing (tests); a lookup for business A cannot read business B's rows (tests).
- A lookup about a person is refused until the caller is verified, and allowed after (tests).

### Boundaries and Next Action

In scope: new module, schema, tests. Out of scope: writing data, the per-business config store (#103, another session) which will carry these declarations later. Next action: write the declaration schema and runner.
